## สิ่งที่ตรวจสอบแล้ว (ยืนยันจากโค้ด + ฐานข้อมูล)

- ตาราง `purchase_orders` มี 2 ใบ (ADVICE-607, SYNNEX-702) ทั้งคู่มี `pdf_url` แล้ว และไฟล์ PDF เปิดได้จริง (HTTP 200, 11 KB, ฟอนต์ไทย Sarabun ปกติ)
- หน้า "ประวัติ PO" (`admin.purchase-orders.tsx`) คลิกแถวได้และพาไปหน้า detail ได้ปกติ **แต่ในตารางไม่มีคอลัมน์เอกสาร/ลิงก์ PDF เลย** — จึงดูเหมือน "ไม่มีเอกสาร"
- หน้า detail มีแค่ปุ่ม "สร้าง PDF" / "เปิด PDF ล่าสุด" ซึ่งเปิดแท็บใหม่ **ไม่มีการแสดงตัวอย่างเอกสารในหน้า** และถ้าเบราว์เซอร์บล็อกป๊อปอัป จะไม่เกิดอะไรขึ้นเลย
- ปุ่ม "ส่งอีเมลถึง Supplier" เรียก edge function `send-po-email` ซึ่ง **ยังไม่มีอยู่จริงในโปรเจกต์** (มีแค่ generate-purchase-order, send-order-confirmation ฯลฯ) → กดส่งจะ error ทุกครั้ง
- `distributor_contacts` ทุกแถวยัง `contact_email = null` → ต่อให้มีฟังก์ชันก็ยังไม่มีปลายทาง

## แผนแก้ไข

1. **หน้า ประวัติ PO** — เพิ่มคอลัมน์ "เอกสาร": ถ้ามี `pdf_url` แสดงปุ่มไอคอนเปิด/ดาวน์โหลด PDF (กดแล้วไม่พาไปหน้า detail), ถ้ายังไม่มีแสดงปุ่ม "สร้าง PDF" เรียก `generate-purchase-order` ตรงจากแถวนั้น
2. **หน้า PO detail** — เพิ่มกล่องพรีวิวเอกสาร (iframe แสดง PDF ในหน้า) พร้อมปุ่มดาวน์โหลด และข้อความสถานะเมื่อยังไม่เคยสร้าง PDF แทนที่จะพึ่งการเปิดแท็บใหม่อย่างเดียว
3. **สร้าง edge function `send-po-email`** — รับ po_id/ผู้รับ/หัวข้อ/เนื้อหา, ดึง PO + สร้าง signed URL ใหม่ (กัน URL หมดอายุ), แนบลิงก์ PDF, ส่งผ่าน Resend เหมือนฟังก์ชันอีเมลอื่น, บันทึกลง `email_logs` และอัปเดตสถานะ PO เป็น "ส่งแล้ว"
4. **เตือนเรื่องอีเมล distributor** — ในหน้า detail ถ้าไม่มี `contact_email` ให้ลิงก์ไปหน้า `/admin/distributor-contacts` โดยตรงเพื่อกรอกอีเมล

## หมายเหตุทางเทคนิค

- signed URL ที่เก็บใน `pdf_url` มีอายุ 1 ปี ใช้แสดงผลได้ แต่ในอีเมลจะสร้างใหม่ตอนส่งเพื่อความชัวร์
- ต้องมี secret `RESEND_API_KEY` อยู่แล้ว (ฟังก์ชันอีเมลอื่นใช้อยู่) จึงไม่ต้องเพิ่มใหม่
